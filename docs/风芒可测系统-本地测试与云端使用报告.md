# 风芒可测系统：本地测试与云端使用报告

## 文档目的
本文档面向研发、运维与演示人员，说明在“实验测试与展示分离”重构后，如何进行本地诊断调优、模型产物管理与云端部署使用。

---

## 1. 本地诊断与模型调优手册 (Testing & Tuning)

### 1.1 运行前准备
1. 确认已安装依赖。
2. 确认数据文件存在于 data/data.csv。
3. 确认配置文件 config/settings.yaml 已存在并包含训练参数与路径。

### 1.2 终端运行指令
在项目根目录执行：

```bash
python main.py
```

Windows 虚拟环境示例：

```powershell
.\.venv\Scripts\python.exe .\main.py
```

### 1.3 交互逻辑展示
程序启动后会进入 CLI 交互菜单：

1. 第一层菜单：
   - A：单模型诊断
   - B：Stacking 融合训练

2. 若选择 A（单模型）：
   - 输入模型编号：
     - 1 = LSTM
     - 2 = XGBoost
     - 3 = GRU
     - 4 = Moirai
   - 流程：训练 -> 测试 -> 下一日预测校验

3. 若选择 B（Stacking）：
   - 输入模型组合，如 1,2,4
   - 流程：
     - 先训练基模型并生成元特征
     - 再训练元学习器（Stacking）
     - 最后进行下一日预测校验

### 1.4 指标解读（业务语义）
#### 回归指标
- MAE（平均绝对误差）：
  预测值与真实值的平均绝对偏差，越小越好，适合直观评估“平均偏差量级”。
- RMSE（均方根误差）：
  对大误差更敏感，越小越好，适合识别峰值场景是否失真严重。
- MAPE（平均绝对百分比误差）：
  从百分比角度衡量误差，便于跨时段、跨量级比较，越小越好。

#### 分类指标（交易信号）
交易信号基于趋势方向（上涨/下跌）生成：
- Precision（精准率）：
  预测为“可执行信号”中，实际正确的比例。高 Precision 表示误触发少，交易更稳健。
- Recall（召回率）：
  实际应触发信号中，被模型捕获的比例。高 Recall 表示机会漏检少。
- F1-score：
  Precision 与 Recall 的综合平衡值，适合作为交易信号总体质量指标。

### 1.5 产物查看路径
#### 图表产物
训练结束后自动静默保存图表到 logs/plots：
- 训练过程图：loss_curve_时间戳.png（等价于常说的 loss_acc_plot.png）
- 拟合效果图：fit_compare_时间戳.png（等价于常说的 fitting_curve.png）

#### 指标日志
- 最新评估日志：logs/metrics/latest_metrics.json
- 内容包含：Precision、Recall、F1、MAE、RMSE、MAPE、是否过拟合、图表路径等。

#### 模型权重
- 最优模型统一保存目录：models/checkpoints/
- 典型命名：
  - lstm_best.pth
  - gru_best.pth
  - xgboost_best.joblib
  - moirai_best.joblib
  - stacking_meta_best.joblib

## 2. 云端迁移与部署变更报告 (Cloud Usage & Migration)

### 2.1 架构变更说明
#### 旧版模式（问题来源）
- 前端 Streamlit + 外部 Flask API 双进程。
- 云端部署时需管理 API 地址、端口、跨进程通信。
- 常见问题：连接超时、服务未就绪、跨域与端口映射失败。

#### 新版模式（当前推荐）
- 采用内部 Service 直接调用（ForecastService/ForecasterManager）。
- app.py 不再依赖外部 Flask 进程。
- 训练与展示彻底分离：
  - main.py 负责训练、评估、固化模型。
  - app.py 负责加载模型并推理展示。

#### Streamlit Cloud 连接问题修复点
通过“逻辑内置 + 单进程推理”规避网络连接链路，消除以下错误根源：
- API URL 配置错误
- 服务启动时序不一致
- 云端端口不可达
- 反向代理与跨进程通信失败

### 2.2 新版操作流程
#### 第一步：离线训练（必须）
在本地运行 main.py，产出 best 模型与指标日志：

```bash
python main.py
```

完成后检查：
- models/checkpoints/ 下存在 _best 权重文件
- logs/metrics/latest_metrics.json 已更新

#### 第二步：配置同步
检查 config/settings.yaml，确保关键项已经固化：
- paths（data/model/checkpoints/logs）
- models（LSTM/GRU/XGBoost/Moirai 参数）
- business.trade（交易阈值）
- horizon（天/周/月融合配置）

#### 第三步：Git 提交
需将以下内容一起提交并推送：
- 代码改动
- config/settings.yaml
- models/checkpoints/（建议至少包含演示所需权重）
- logs/metrics/latest_metrics.json（可用于云端回显历史指标）

建议命令：

```bash
git add .
git commit -m "refactor: split training and inference, add config center and checkpoint loader"
git push
```

#### 第四步：云端 Secrets 配置
在 Streamlit Cloud 项目设置中，添加 Secrets（TOML）：

```toml
[database]
host = "your-db-host"
port = 3306
user = "your-db-user"
password = "your-db-password"
database = "your-db-name"
```

读取优先级为：
1. st.secrets
2. config/settings.yaml

### 2.3 一键运行指令
云服务器或 Streamlit Cloud 环境中，仅需执行：

```bash
streamlit run app.py
```

无需再额外启动 Flask 进程。

## 3. 运维建议与验收清单

### 3.1 最小验收清单
- main.py 可完成一次训练/评估并输出日志。
- models/checkpoints/ 中存在可加载的 best 模型。
- app.py 启动后可直接点击“开始预测”。
- 若缺少 checkpoints，页面出现红色提示框引导先执行 python main.py。
- 历史指标页能读取 latest_metrics.json 并展示 Precision/Recall/F1。

### 3.2 推荐发布节奏
1. 本地训练并冻结参数。
2. 产物与配置一起提交。
3. 云端更新 Secrets。
4. 启动 Streamlit 并进行一次冒烟预测。
